# paper-claim-ledger：把论文结论落到"我的设定"，并让每个判断能回到原文

## 1. 解决什么问题

研究者读方法论文时常犯三类错：
1. **越界**：把论文在 A 设定下的结论，直接套到自己的 B 设定。
2. **混层**：把论文原述、作者的推断、读者自己的联想写在同一段，事后分不清谁说了什么。
3. **虚引**：AI 摘要里的"原文引用"和页码常不是原文，读者无法核对。

本 Skill 的产物不是摘要，而是一份**决策型阅读报告**：针对用户的一个具体问题，给出结论、适用边界、证据位置、缺口和下一步。

## 2. 何时使用 / 不使用

使用：用户给出 ① 一篇论文(PDF 或带页码文本) ② 一个具体决策问题(例如"我的设定能不能用这个方法/这个结论说明什么")③ 自己的设定(至少数据结构、所用方法/软件、样本规模)。

不使用，或先停下来询问：
- 没有具体问题，只说"总结一下"→ 先问"你要用这篇论文做什么决定"，或给出最多 3 个候选问题让用户选。
- 一次给了多篇论文却问一个问题 → 逐篇各跑一遍，最后单独写跨文献对照，不要混在一份台账里。
- PDF 无文本层(扫描件) → 见第 7 节，不能产出"逐字引文"。

## 3. 输入 / 输出契约

输入：`paper.pdf`、`question`(一句话决策问题)、`my_setting`(用户设定，缺项允许但要显式列为缺口)。
输出(写在用户指定目录，默认 `./out/`)：

| 文件 | 内容 |
| --- | --- |
| `report.md` | 最终报告(结构见第 6 节) |
| `claims.json` | 论点-证据台账(结构见第 4 节)，是报告的唯一事实来源 |
| `verify_report.json` | `verify_quotes.py` 的核验结果，必须 `fail=0` |
| `work/` | `pages.json`、`pages.txt`、`extract_report.json`、渲染的页面图 |

## 4. 台账结构 `claims.json`

```json
{"question":"...","my_setting":{"...":"..."},
 "claims":[
  {"id":"F1","label":"fact","statement":"论文说了什么(一句话)","page":5,
   "quote":"原文逐字摘录,>=12字符","quote_type":"text"},
  {"id":"F2","label":"fact","statement":"某公式的位置","page":8,
   "quote_type":"formula","anchor":"紧邻公式的同页散文句,逐字"},
  {"id":"I1","label":"inference","statement":"从F1,F2推出的、论文没明说的结论","based_on":["F1","F2"]},
  {"id":"U1","label":"unknown","statement":"论文没覆盖的点","gap":"缺什么信息",
   "next_reading":"去哪里核查(只写论文参考文献里出现过的文献,或明确写成'查找建议,未确认存在')"}]}
```

三类的硬规则：
- **fact**：只能是论文白纸黑字写的内容。必须有页码和逐字引文，引文以 PDF 页序为准；数字、符号、限定词(如 "only", "may", "in our simulation")必须原样保留，**限定词不能丢**。公式不手抄，只给页码 + 同页紧邻的散文 `anchor`。
- **inference**：由 fact 推出而论文没明说的内容。必须列出 `based_on`，且不得自带引文。
- **unknown**：论文没有覆盖、或用户设定缺失导致无法判断的内容。必须写 `gap` 和 `next_reading`。

## 5. 工作流程(按顺序，不跳步)

**Step 0 范围闸门。** 用一句话写下 `question`；列出 `my_setting` 中已知项与缺项。缺项若会改变答案(例如用户没说用的是哪个软件/默认选项)，要么问用户(最多 3 个问题)，要么在报告里把"该项取不同值时答案如何变"写成分支，不得默默假设。

**Step 1 抽页与诊断。** 运行：
`python scripts/extract_pages.py paper.pdf --out out/work/ --render <图表页>`
读 `extract_report.json`：`text_layer_ok=false` → 转第 7 节。`pages_figure_like` 里的页面必须渲染成图并目视读，图里的数值/形状只能写成"目视近似"并标注页码，**不得写成已核验的数字**。

**Step 2 论文地图。** 通读全文(不是只读摘要和结论)。建一张"论文设定表"：论文研究的对象/设定、关键假设、方法或估计量、证据类型(定理/仿真/实证/讨论)、证据规模(几个设定、几次抽样、几个数据集)。证据类型和规模决定结论强度——**仅一次仿真或一个案例的结果，不能写成"普遍成立"**。

**Step 3 建台账。** 围绕 `question` 逐条记录 fact，再写 inference 和 unknown。每条 fact 回到原页确认语境：上下文里有"在本节的设定下/默认设置下/在某假设下"这类限定，必须带进 statement。

**Step 4 设定对照。** 逐项比较论文设定与用户设定，每项判为 `一致 / 部分一致 / 论文未覆盖 / 不一致`，并指向对应 claim id。**"论文未覆盖"的项一律不得由 fact 支撑**，最多是 inference 或 unknown。

**Step 5 核验(强制)。** 运行：
`python scripts/verify_quotes.py out/claims.json out/work/pages.json --out out/verify_report.json`
有 FAIL 就修：`WRONG_PAGE` 改页码，`NOT_FOUND` 回到原页重新摘录或降级为 inference/unknown。最多迭代 3 轮；仍未通过的论点从结论中删除，并在"核验记录"里写明。**未通过核验的内容不得出现在结论里。**

**Step 6 写报告**(结构见下)。**Step 7 自检**：对照第 8 节清单，逐项勾选，写入报告末尾。

## 6. `report.md` 结构(顺序固定)

1. **一句话结论**(≤120 字)：先回答 `question`，说明强度(确定/有条件/无法判断)。
2. **适用性对照表**：设定项 | 论文设定 | 我的设定 | 判断 | 依据(claim id)。
3. **原文事实**：每条 `F*`：页码、逐字引文(引用块)、一句话含义。
4. **推断**：每条 `I*`：推理链(引用 F*)、为什么论文没直接说、可能出错的地方。
5. **未知与后续阅读**：每条 `U*`：缺什么、为什么影响决策、去哪里查。
6. **下一步操作**：按优先级给 3–5 条用户现在就能做的具体动作；标明哪些来自论文建议(F*)，哪些是你的建议(I*/经验)。
7. **核验记录**：脚本结果(total/pass/fail)、修正过的论点、仍存的限制、本次运行的耗时/人工介入。

## 7. 异常处理

| 情形 | 预期行为 |
| --- | --- |
| 无文本层(`text_layer_ok=false`) | **不产出带引文的 fact**。说明原因；可目视读图并标注"目视、未经文本核验"；请用户提供文本版(arXiv 源、出版社 HTML)或授权 OCR；给出 OCR 后再跑本 Skill 的指引。不编造页码和引文。 |
| 论文没有回答该问题 | 明说"本文不能回答"，列出论文**实际**回答了什么、缺口是什么、去哪里找；不要硬凑。 |
| 用户设定缺失致答案分叉 | 给出分支结论，列出需要用户补的 1–3 个信息。 |
| 脚本/依赖不可用 | 说明哪一步没跑；手工逐条核对时，在核验记录里标注"未经脚本核验"，且不得声称 pass。 |
| 引文只出现在别的页 | 修页码；仍冲突则按页序为准。 |

## 8. 提交前自检清单(逐项回答 是/否)

- [ ] 结论段回答了 `question` 本身，而非复述摘要。
- [ ] 每条 fact 有页码+逐字引文，且 `verify_quotes.py` 全部 PASS。
- [ ] 没有把论文设定外的结论写成 fact。
- [ ] 论文的限定词(仅仿真/默认设置/某假设下)都保留在 statement 里。
- [ ] 来自图的数字标了"目视近似"。
- [ ] 每条 unknown 有 gap 与 next_reading；后续阅读只指向论文参考文献里的条目或明示"查找建议"。
- [ ] 区分了"论文建议"与"我的建议"。
- [ ] 核验记录里如实写了失败、重试和未完成项。

## 9. 不做的事

- 不手抄公式冒充原文；不改写引文；不"润色"论文措辞后仍放进引用块。
- 不评价论文总体好坏，不做同行评审；只回答 `question`。
- 不替用户跑他们的数据；可以给出该用什么设置重跑，但不声称已经重跑。
