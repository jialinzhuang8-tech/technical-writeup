# 让 AI 读方法论文时"每个判断都能回到原页"：一个可复现的实践

> 一个具体问题：**我用 R `did` 包默认设置画的事件研究图，处理前系数贴近 0，能不能在论文里写"平行趋势得到验证"？**
> 这篇分享用一篇真实论文、六次独立运行、盲评打分，回答"让 AI 怎么读才靠谱"，并如实记录哪些有效、哪些没效。

- 论文：J. Roth, *Interpreting Event-Studies from Recent Difference-in-Differences Methods*, arXiv:2401.12309v2（2026-01-16，CC BY 4.0）
- 正文入口：本文件。证据在 `case_roth_event_study/`，方法实现在 `skill/`。
- 工具：Python 3.13 + PyMuPDF；AI 宿主为 WorkBuddy 桌面 Agent（**模型型号无法取得**）。

---

## 1. 阅读难点到底卡在哪

读方法论文做决策，AI 最常在三处出错（我自己读论文时也常犯）：

| 难点 | 表现 | 后果 |
| --- | --- | --- |
| 越界 | 论文在"非交错、单次仿真"下的结论被直接套到"三批交错进入"的设定 | 写进论文的结论超出论文证据 |
| 混层 | 论文原述、AI 的推断、作者自己的措辞建议混在同一段 | 事后分不清"这是论文说的还是我说的" |
| 虚引 | "原文引用"和页码不是原文 | 评审/导师一查就破 |

这三点里，**第三点可以机械检查，前两点只能靠结构约束**。方法就是据此设计的。

## 2. 方法：三层台账 + 一个强制核验脚本

1. `extract_pages.py`：PDF → 带页码文本；诊断"无文本层/图表页"。
2. 让模型写一份 `claims.json`：每条论点必须标 `fact / inference / unknown`。
   - `fact`：必须有页码和**逐字**引文；公式只给页码和同页的散文锚点。
   - `inference`：必须列出依据的 fact，且不得自带引文。
   - `unknown`：必须写缺什么、去哪里查。
3. `verify_quotes.py`：对每条 fact 在所标页查找引文；错页码报 `WRONG_PAGE`，编造报 `NOT_FOUND`。
4. 报告只能由台账生成，且结构固定：结论 → 设定对照表 → 事实 → 推断 → 未知 → 下一步 → 核验记录。

为什么这样设计：我不信任"AI 自己说它核对过了"，所以把**最容易作弊的环节（页码+逐字引文）**交给脚本，把**必须靠判断的环节（适用性）**交给结构。脚本冒烟测试中，故意制造的错页码、编造引文、悬空依据、缺失 `next_reading` 全部被拦下。

## 3. 真实案例与结果

**任务**（`case_roth_event_study/A_task.md`）：用户是多期 DID 的研究生（2017/2020/2022 三批进入，约 280 处理企业，从未处理对照），用 `did` 默认设置，前 4 期系数≈0，t+4/t+5 显著。问：能不能写"平行趋势得到验证"？论文建议怎么画图与汇报？

### 3.1 论文原文怎么说（均已逐字核对，页码为 PDF 页序）

- 默认事件研究图不应按传统 TWFE 方式解读（p.2）。
- CS 默认构造不对称：处理前是"相邻期短差分"，处理后是"相对处理前一期的长差分"（p.7）。
- 论文的仿真：**处理效应为 0，但处理组相对对照组线性上升（γ=0.5）**——TWFE 图是直线，CS 默认图处理前较平、处理时点出现拐点（p.3, p.5, p.8）。
- 修正：`base_period = "universal"`（Stata `csdid` 用 `long2`），论文称在其**非交错**设定中与动态 TWFE 数值等价（p.10）。
- 论文也说：这并不威胁处理后估计的有效性（若相应平行趋势成立），问题在于难以**用视觉**判断（p.12）。
- 样本构成会随相对时间变化，建议补"各队列结果均值时序图"或做平衡性限制（p.12–13）。

### 3.2 哪些是推断，哪些论文没覆盖（我的判断，非论文原述）

- 推断：用户 3 批交错进入、面板到 2024 年 → t+5 只有 2017 批能贡献，t+4 只有 2017 与 2020 批能贡献（按用户给的年份算术推出，论文没算）。
- 论文没覆盖：交错设定下默认图失真的形状；CS + HonestDiD 的具体操作；该样本量下前趋势检验的功效。

## 4. 对照实验：Skill 到底有没有用？（如实）

同一任务、同一 PDF、同一宿主默认模型；每次是独立新会话；验收标准在运行前冻结（`A_acceptance.md`）；由**另开的评分员**对去标识、随机编码的报告打分，并被要求自己在论文文本中核对引文与页码。共 3 对（6 次）。

| 运行 | 总分/30 | 核心结论 R/12 | 证据 Q/8 | 适用性 G/6 | 可用性 U/4 | 引文 fact 数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| with-1 | 28 | 11 | 8 | 5 | 4 | 24 |
| with-2 | 29 | 12 | 8 | 5 | 4 | 26 |
| with-3 | 28 | 11 | 8 | 5 | 4 | 27 |
| without-1 | 29 | 12 | 7 | 6 | 4 | — |
| without-2 | 24 | 12 | 5 | 4 | 3 | — |
| without-3 | 24 | 12 | 6 | 3 | 3 | — |
| **with 均值** | **28.3** | 11.3 | **8.0** | 5.0 | **4.0** | |
| **without 均值** | **25.7** | **12.0** | 6.0 | 4.3 | 3.3 | |

**怎么读这张表（不要读成"Skill 完胜"）：**
1. **核心结论的正确性，两边都对**——without 反而略高（12.0 vs 11.3）。这篇论文很短（15 页），整篇塞进上下文，普通 AI 也能读对主旨。
2. **差异在证据可追溯性**：with 三次 Q 都是满分；without 三次都在 Q3（区分原文/推断）被压到 1 分，其中两次出现"把自己的措辞建议列在'论文建议的做法'下"或"改写后仍放入引号"。
3. **没有稳定的总分优势**：without-1 拿了 29，与最好的 with 持平。三对样本太少，不能说显著。
4. **代价**：with 侧耗时 201–265 s，without 侧 81–119 s，**约 2–3 倍**。
5. with 侧 77 条 fact 引文，用我另写的独立脚本复核：**77/77 逐字存在于论文且页码正确**；这是脚本强制核验的直接结果。without 侧没有同类硬约束，评分员人工发现 2 条改写后仍放入引号。

## 5. 一个值得分享的"坑"

`verify_quotes.py` v1.0.0 在两次运行（with-2、with-3）的首轮核验中共有 3 条失败，原因相同（with-1 与 B 案例首轮全部通过）：论文 PDF 在行末把 `pre-treatment` 断成 `pre-` / `treatment`，提取文本是 `pre-\ntreatment`；脚本把断词连字符去掉得到 `pretreatment`，而模型引用时写的是带连字符的 `pre-treatment`，于是**对的引文被判成错**。全文有 28 处这类断行连字符。

- 影响：误报会让 Agent 去"修正"本来正确的引文，或者降级成推断。
- 当前处理：执行者截取更短的逐字片段后重跑，两次都在第 2 轮通过（SKILL.md 的失败处理写的是"回到原页重新摘录"，并未明说这一点，v1.1 应补）。
- 未做：脚本本身没改（改了就破坏版本一致性，留给 v1.1：对两侧同时去除连字符再比较）。
- 同样的思路适用于任何"逐字引文校验"：**比较前两边必须用同一套规范化**。

## 6. 复现步骤

```bash
pip install pymupdf
mkdir r && cd r && mkdir input out
cp ../case_roth_event_study/input/roth_2401.12309v2.pdf input/
cp ../case_roth_event_study/A_task.md task.md
cp -R ../skill skill            # without 对照就不要这一行
# 在一个全新的 Agent 会话里: "读 task.md；若有 skill/ 则严格按 skill/SKILL.md 执行；产物写到 out/"
python skill/scripts/verify_quotes.py out/claims.json out/work/pages.json   # 仅 with 侧
```
结果检查：打开 `case_roth_event_study/A_acceptance.md`，逐项对照；在 `input/roth_2401.12309v2.pages.txt` 里搜引文核对页码。第一次最好让没看过运行过程的人盲评。

## 8. 局限
