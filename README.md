# 让 AI 读方法论文时"每个判断都能回到原页"：paper-claim-ledger v1.1 的实践与对照

> 一个具体问题：**我用 R `did` 包默认设置画的事件研究图，处理前系数贴近 0，能不能在论文里写"平行趋势得到验证"？**
> 本文用一篇真实论文、6 次独立运行、盲评打分，回答"让 AI 怎么读才靠谱"，并如实记录哪些有效、哪些没效，以及一个 v1.0 到 v1.1 的真实修复。

- 论文：J. Roth, *Interpreting Event-Studies from Recent Difference-in-Differences Methods*, arXiv:2401.12309v2（2026-01-16，CC BY 4.0）
- 正文入口：本文件。方法实现在 `skill/`，证据在 `case_roth_event_study/`，复用与异常案例在 `other_cases/`，早期版本在 `archive_v1.0/`。
- 工具：Python + PyMuPDF；AI 宿主为 WorkBuddy 桌面 Agent（**模型型号与成本无法取得**，宿主未暴露）。
- 本文只覆盖通用技术分享，**未使用玻尔科学空间**，不涉及其生态贡献项。

---

## 1. 阅读难点到底卡在哪

读方法论文做决策时，AI（和人）最常在三处出错：

| 难点 | 表现 | 后果 |
| --- | --- | --- |
| 越界 | 论文在"非交错、单次仿真"下的结论，被直接套到"三批交错进入"的设定 | 写进论文的结论超出论文证据 |
| 混层 | 论文原述、AI 推断、作者自己的措辞建议混在同一段 | 事后分不清"是论文说的还是我说的" |
| 虚引 | "原文引用"和页码不是原文 | 评审/导师一查就破 |

**第三点可以机械检查；前两点只能靠结构约束。** 方法按此设计。

## 2. 方法：三层台账 + 一个强制核验脚本

| 步骤 | 作用 | 机械/判断 |
| --- | --- | --- |
| Step 0 范围闸门 | 一句话 question；列出用户设定的已知项与缺项 | 判断 |
| Step 1 `extract_pages.py` | PDF 按页拆分；识别无文本层页/图表页；无文本层时退出码 3，不得硬做 | **机械** |
| Step 2–4 论文地图 / 台账 / 设定对照 | 每条论点标 `fact / inference / unknown`，限定词必须带入 | 判断 |
| Step 5 `verify_quotes.py` | `fact` 的引文必须逐字出现在所标页；`inference` 须列出 `based_on`；`unknown` 须写缺什么、去哪查 | **机械** |
| Step 6–7 报告 + 自检 | 固定结构；区分"论文建议"与"我的建议" | 判断 |

关键规则：
- `fact`：页码（PDF 页序）+ **逐字**引文；公式不手抄，只给页码和同页散文锚点；图里的数字只能写"目视近似"。
- `inference`：必须列出依据的 `fact`，不得自带引文。
- 报告只能由台账生成。无文本层时**不得**产出任何引文。

为什么这样设计：不信任"AI 自己说它核对过了"，所以把最容易作弊的环节（页码 + 逐字引文）交给脚本，把必须靠判断的环节（适用性）交给结构。脚本冒烟测试中，故意构造的错页码、编造引文、悬空依据、缺失 `next_reading` 全部被拦下（退出码 1）。

## 3. 真实案例

**任务**（`case_roth_event_study/A_task.md`）：用户是多期 DID 研究生（2017/2020/2022 三批进入，约 280 处理企业，从未处理对照），用 `did` 默认设置，前 4 期系数≈0，t+4/t+5 显著。问能不能写"平行趋势得到验证"，论文建议怎么画图与汇报。

### 3.1 论文原文怎么说（Skill 运行产出，均经脚本逐字核验；页码为 PDF 页序）
- 默认事件研究图不应按传统动态 TWFE 的方式解读（p.2）。
- CS 默认构造**不对称**：处理前系数是相邻期"短差分"，处理后是相对处理前一期的"长差分"（p.7）。
- 论文的仿真：**处理效应为 0，但处理组相对对照组线性上升（γ=0.5）**。TWFE 图是直线，CS 默认图处理前较平、处理时点出现拐点（p.3, p.5, p.8）。这是**单次仿真**，不是实证发现。
- 修正：`base_period = "universal"`（Stata `csdid` 用 `long2`），论文称在其**非交错**设定中与动态 TWFE 数值等价（p.10）。
- 论文也说：这并不威胁处理后估计的有效性（若相应平行趋势成立），问题是难以**用视觉**判断（p.12）。
- 样本构成会随相对时间变化，建议补"各队列结果均值时序图"或做平衡性限制（p.12–13）。

### 3.2 推断与未覆盖（报告者判断，非论文原述）
- 推断：用户面板到 2024 年，t+5 只有 2017 批能贡献，t+4 只有 2017、2020 批能贡献（按用户给的年份算术推出，论文没算）。
- 论文没覆盖：交错设定下默认图失真的形状；CS + HonestDiD 的具体操作；该样本量下前趋势检验的功效。

## 4. 对照实验：Skill 到底有没有用（如实）

同一任务、同一 PDF、同一宿主默认模型；每次独立新会话、只能访问自己的目录；验收标准**运行前冻结**（`A_acceptance.md`，30 分）；6 份报告去标识并随机编码后，由另开的评分员打分，并被要求自己在论文文本中核对引文与页码。with 侧为 **v1.1.0**（`skill/` 目录哈希 `1d5b753ff54c`，6 次 with 运行已逐个核对一致）。

| 运行 | 总分/30 | 核心结论 R/12 | 证据 Q/8 | 适用性 G/6 | 可用性 U/4 | 硬性扣分 | 耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | --- | ---: |
| with-1 (v1.1) | 29 | 11 | 8 | 6 | 4 | 无 | 495 s* |
| with-2 (v1.1) | 29 | 12 | 8 | 5 | 4 | 无 | 152 s |
| with-3 (v1.1) | 29 | 11 | 8 | 6 | 4 | 无 | 278 s |
| without-1 | 29 | 12 | 7 | 6 | 4 | 无 | 81 s |
| without-2 | 25 | 12 | 5 | 5 | 3 | X1 轻度 | 88 s |
| without-3 | 25 | 12 | 6 | 4 | 3 | X1 轻度 | 119 s |
| **with 均值** | **29.0** | 11.3 | **8.0** | 5.7 | **4.0** | | |
| **without 均值** | **26.3** | **12.0** | 6.0 | 5.0 | 3.3 | | |

\* with-1 日志里有十余次宿主工具层报错并自行恢复，耗时偏长与 Skill 无关。X1 = 把论文原述与推断/自己的建议混写。

**怎么读这张表（不要读成"Skill 完胜"）：**
1. **核心结论的正确性两边都对**，without 反而略高（12.0 vs 11.3）。这篇论文只有约 15 页，整篇塞进上下文，普通 AI 也能读对主旨。
2. **差异在证据可追溯性**：with 三次 Q 都是满分；without 三次 Q 都不满，其中两次触发 X1，without-2 另有一条引文被缩写后仍放在引号里（20/22 逐字）。
3. **没有稳定的总分优势**：without-1 拿了 29，与 with 持平。三对样本不能说显著。
4. **代价**：with 约为 without 的 **1.5–5 倍耗时，典型 2–3 倍**。
5. 引文：with 三份台账 fact 引文 23 / 32 / 23 条，脚本核验全部通过；评分员对报告正文英文引文的人工核对为 with-1 23/23、with-2 36/36、with-3 23/23；without-1 14/14、without-2 20/22、without-3 8/8。
6. v1.0（早期版本，archive）的方向相同：28.3 vs 25.7。

### 复用与异常（同一 v1.1，未改 Skill）
- **B（换论文、换方法族）**：Alvarez & Ferman (2023)，纯理论推断笔记，无仿真无实证。19/20；评分员抽查 10 处引文、9 处页码全部正确；正确指出"论文无仿真/实证"和"命题 2 的条件成立才有效"。扣分点：后续阅读文献没有明说"我未读过"。B 只跑了一次，无 without 对照。见 `other_cases/B/`。
- **C（构造的扫描件）**：把 A 的第 2 页渲染成无文本层 PDF。两次独立运行均 10/10：诊断 `text_layer_ok=false`，不产出任何引文，结论"无法判断"，给出恢复路径；评分员把目视笔记逐句对照该页真实文字，两次的 11 条与 10 条断言均有对应，没有凭记忆补写。见 `other_cases/C/`。

## 5. 值得分享的发现：一个"校验器自己出错"的坑

**现象**：`verify_quotes.py` v1.0.0 在两次运行（with-2、with-3）的首轮核验中共 3 条失败，而这些引文其实是对的。

**原因**：PDF 在行末把 `pre-treatment` 断成 `pre-` / `treatment`，提取文本是 `pre-\ntreatment`。脚本只对页面文本去掉断行连字符，得到 `pretreatment`；模型引用时写的是带连字符的 `pre-treatment`，于是**对的引文被判成错**。全文有 28 处这类断行连字符。

**影响**：误报会让 Agent 去"修正"本来正确的引文，或把 fact 降级成推断。v1.0 里两次运行的执行者都是自行截取更短的片段才通过，而 SKILL.md 当时并未写明这一做法。

**修复（v1.1）**：比较时**两侧同时去掉所有连字符并转小写**，只在连字符上放宽，其他字符仍须逐字一致。
**验证**：①原失败用例通过；②错页码 / 编造引文 / 悬空依据的负面用例仍全部被拦；③四份 v1.0 历史台账（36/39/39/53 条）回归全部通过；④v1.1 重跑的 with 运行首轮 verify 全部通过（with-3 一次 `FileNotFoundError` 来自并行读写，重跑即过）。

**可迁移的规律**：任何"逐字引文校验"，**比较前两边必须用同一套规范化**；否则校验器会把对的当成错的，Agent 的"修正"会反过来引入错误。

## 6. 复现步骤

在本仓库根目录执行（`PY` 换成已装 PyMuPDF 的 Python）：

```bash
pip install pymupdf
PY=python3
mkdir -p r/input r/out
cp case_roth_event_study/input/roth_2401.12309v2.pdf r/input/
cp case_roth_event_study/A_task.md r/task.md
sed -i.bak 's#materials/A/#input/#' r/task.md       # 任务里的路径指向 input/
cp -R skill r/skill                                  # without 对照不要这一行
cd r

$PY skill/scripts/extract_pages.py input/roth_2401.12309v2.pdf --out out/work/
#   读 out/work/extract_report.json：text_layer_ok=false 时按 SKILL.md 降级
$PY skill/scripts/extract_pages.py input/roth_2401.12309v2.pdf --out out/work/ --render 4,6   # 图页渲染成 png

# 在一个全新的 Agent 会话里发这条指令:
# "工作目录是当前目录。先读 task.md，再完整读 skill/SKILL.md 并严格按 Step 0–7 执行，包括运行
#  skill/scripts/ 里的两个脚本。产物写到 out/，过程与失败记录到 out/run_log.md。"

$PY skill/scripts/verify_quotes.py out/claims.json out/work/pages.json --out out/verify_report.json
```

**怎么判断跑通**：①`verify_quotes.py` 退出码 0 且 `fail=0`；②`out/` 下有 `report.md`、`claims.json`、`verify_report.json`；③报告含 SKILL.md 第 6 节规定的 7 个部分。
**怎么评价结果**：对照 `case_roth_event_study/A_acceptance.md` 逐项打分；在 `case_roth_event_study/input/roth_2401.12309v2.pages.txt` 里搜引文核对页码。最好让没看过运行过程的人盲评。
**校验 Skill 版本**：`cd skill && find . -type f ! -name '*.pyc' | LC_ALL=C sort | xargs shasum -a 256 | shasum -a 256 | cut -c1-12`，应得到 `1d5b753ff54c`。

干净目录复跑：一个只拿到 README 的全新会话按旧 README 复跑，跑通到 verify 33/33 全 PASS，但暴露 12 条 README 缺口和 7 处写错（`case_roth_event_study/grading/clean_dir_repro_log.md`）。本节命令是据此重写的；**重写后没有再让另一个会话复跑**，所以"已无缺口"尚未被证实。
